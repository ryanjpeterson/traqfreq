traqfreq · build phases

Each cut-over is one release of each app: traqfreq gains the write and jimbo-dj turns its version off. If a cut-over goes wrong, roll it back in traqfreq (its tables go aside, reads return to jimbo-dj’s copy) and switch jimbo-dj’s back on; jimbo-dj’s data hasn’t been touched. jimbodj-text and the native analyzer stay as they are.
