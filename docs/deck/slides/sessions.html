How sessions work

One session, one window, one pull request

START · SMALL

Read only what the session needs

CLAUDE.md (one page), HANDOFF.md, and the one spec in docs/specs. No reading jimbo-dj beyond the functions it reuses.

BUILD · TESTED

Fixture database, not the real one

Tests run on a small generated copy of jimbo-dj’s schema, so cloud sessions never need your library.

END · HANDED OFF

Push, note, deck

Tests green, pull request open, HANDOFF.md says done and next, and this deck’s status and log are updated.

New chat at the start of each phase, or sooner when a chat grows long. The handoff note and this deck carry everything across.

On the Mac mini: from T2, sessions run in jimbos-sloppydrive/traqfreq on the Mac mini, driven from the laptop by Remote Control, so gates run in the same session.

traqfreq · build phases

Token-efficient by design: each session starts from a one-page CLAUDE.md, the handoff note and one spec, never from this long planning conversation. If a usage window runs low, the session stops at the last green commit and writes the handoff.
